# Quote previews and body-search navigation

The 2026-10-14 preview feedback adds three outcomes to v0.3.3.2, following the four completed editor and workspace-ordering outcomes. Scope was recorded in TODO before implementation; the version contains seven product issues.

## Product outcomes

1. Clicking or tapping anchored words opens a persistent speech bubble above the quote's right end without changing reader layout or text. The bubble's Edit action opens the existing editor. Outside click, repeated quote click, Escape and an explicit close action dismiss it; pointer travel has no timeout. Placement prefers above/right, stays within viewport bounds, follows visible anchors while scrolling, hides when the anchor is outside the visible reader, and permits independent scrolling of long note content. The original quote rail retains its viewer and management actions. A repeated quote uses its existing safe anchor rather than attaching to the first identical sentence.
2. Search navigation retains the first matched passage as the scroll destination and paints all query occurrences in the complete rendered article. Marks remain throughout reading, track scrolling, resize and image loads, and clear when editing or navigating away. Painting uses the browser's native CSS Highlight registry, so marks inherit text clipping and scroll with their text through the compositor. The search highlight has priority over overlapping annotation paint. No detached layer, scroll-coordinate copying or per-frame repaint loop is used, and serialization and annotation ranges remain untouched.
3. The index contains only the editable reviewed article text, including its title and headings. Trusted source metadata, raw text, reflections and annotations are excluded. Versioned file signatures rebuild legacy body rows automatically, and reconciliation removes every legacy non-body row. Search UI has no content-scope selector or misleading annotation/body split. HTTP and MCP keep `all` as a body-only compatibility alias; unsupported fields are rejected. The CLI accepts only `reviewed` and `all`.

## Verification

Browser cases cover light/dark, desktop/tablet/mobile, repeated anchors, Markdown preview, persistent bubbles after pointer travel, above/right placement and bubble tails, toggle/outside/Escape/explicit closing, reachable editing, long-note scrolling, saved notes, touch tapping, article-file preservation, all three Chinese occurrences, highlight persistence beyond the previous timeout, resized/scrolled geometry, edit-mode cleanup, route cleanup and exclusion of private-note results. Backend tests verify automatic legacy migration, excluded scopes, protected metadata, unchanged sidecars, source edits and stale passage validation. The initial full regression on 2026-10-14 passed 302 backend tests, 51 frontend tests and all 31 browser cases. After the native-paint correction, all five affected search/annotation browser cases and the production build/type-check pass. Type-check, production build, source compilation, configuration JSON and diff checks pass. The local preview was restarted with its existing runtime; all 20 article files retained their checksums, both saved annotations remain available, and its body-only search returns the expected three occurrences.

Later quote-preview feedback replaced hover timing with a click-open speech bubble under the same existing outcome. The final bubble revision passes all 32 browser regressions, including three bubble cases at 1440px, 1024px and 390px, and production build/type-check. The existing preview also passes pointer-leave persistence and reachable Edit checks in an isolated browser without changing its saved notes.

Preview feedback exposed a detached-layer clipping bug and rapid-scroll lag in the initial implementation. Acceptance was reopened under the existing complete-highlighting outcome, and the native-paint correction is checked with rapid alternating inner/page scroll positions, real wheel input and a pixel comparison proving that offscreen highlighted text cannot paint into the desktop toolbar. A fresh isolated browser also checks the existing local preview: all three native search ranges remain present, no detached highlight layers exist, and no page errors occur.

The existing editor worktree remains the development base. This task does not tag, publish or create a new release branch; the v0.3.3.1 merge-back gate remains in TODO.
