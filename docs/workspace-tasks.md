# Workspace tasks and live review

The dashboard's **Current runs / 当前任务** includes capture, article review, upload, reflection polish and batch jobs. Jobs started from an article page appear here too. Only queued and running jobs appear in Current runs. Completed, cancelled, failed and paused jobs appear in Task history; open an article or batch from its task entry. Each tab counts only its own tasks. The former standalone badge counted all retained jobs, including completed ones; it was not a pending approval count.

For an article that has only been captured, open it, choose **Edit / 编辑**, select a review perspective and choose **Review with AI / 按此视角审阅**. You can return to the dashboard while review continues. Its article list, reviewed count and Collection navigation refresh when the job changes state or finishes.

**AI review complete / AI 审阅完成** means that the reviewed article has already been saved. There is no extra approval button or required confirmation step. You may read or edit it, and upload it explicitly when ready. The capture task is a completed history record: later saves and uploads do not advance it to a different state, and uploads have their own jobs. For compatibility, this terminal task state remains `awaiting_review` in the API; the article itself is `reviewed`.

A Zhihu login, security-verification or access-denied page is a capture failure, even if the crawler reports success. Noosphere tries the configured fallback crawler, then stops before saving a fake article or invoking AI if no article body is available. Existing invalid capture records are retained for inspection; this check does not rewrite their original files.

Current tasks keep a compact progress bar and an **Open article / 打开文章** entry. The existing workbench, Noosphere background and knowledge navigation are retained. Detailed output belongs to the article in the knowledge workspace.

Capture and review durations cannot be measured as a percentage while the model is generating. Their activity bars show the actual stage without a numeric estimate: text review, image processing and classification. Before the first article text arrives, the reading area remains blank, without waiting text or a cursor. Provider events and text chunks never advance a fabricated percentage. Successful classification and publication complete the task automatically and move it into history; no manual completion action is required. For these running jobs the API's `progress` is `null`, becoming `100` after successful publication. Parallel long-article parts buffer later text until earlier parts are available, without repeatedly publishing empty previews.

Once extraction succeeds, the article is available even while AI review is running. A newly captured article remains unfiled until the complete review and final classification succeed. Open it from the task or knowledge sidebar to watch rendered Markdown appear continuously. Internal JSON, summaries and image-layout responses are excluded; parallel long-article parts appear in source order. Returning to the dashboard shows the same job's progress; reopening the article continues the same review.

A new review clears only the visible preview and keeps it visible throughout startup, including delayed job and article refreshes. The starting article does not flash back between clearing and new output. It uses the saved current draft, with unsaved edits saved first. Review text, metadata enrichment, image changes and classification are staged separately; the saved starting article stays intact until successful publication. Choose **Cancel review / 取消审阅** during generation or classification to stop the job and restore that starting article, including its images, metadata, classification and review count. Reflections, annotations and original `raw.md` remain independent. Saved edits made from another window are protected by the starting revision and are never overwritten by the review.

A short adaptive buffer smooths incoming text and follows the output until you scroll up or choose Stop following. Choose Follow output to resume. The transparent status bar stays above the scrolling article without covering its text or hiding the Noosphere atmosphere. Scrolling up, using Page Up, dragging the scrollbar or choosing an earlier outline heading pauses following. New text, layout changes and image loading continue following while it is enabled; they do not re-enable it after you pause. Background completion does not flush the buffer: every remaining character finishes displaying before the saved editor returns. Cancellation or failure discards the new preview and displays the saved article. Failed captures retain the explicit Retry action.

Completed Markdown blocks stay stable while the current block grows, reducing long-article rendering pauses. Lists, tables, code, local images, reference links and document-wide footnotes retain their Markdown meaning. A pause in upstream model output can still pause new text; the interface does not invent text while waiting for the next response.

Reloading or reconnecting restores the current task snapshot and continues live updates. If the live connection is unavailable, the interface falls back to periodic job refreshes. A service restart marks interrupted jobs as failed and requires an explicit retry, as before.

After updating a running installation, reload its browser page to load the new interface. The application entry page requires cache revalidation; content-hashed assets retain their normal caching behavior.

The shared job API remains `GET /api/v1/jobs` and `GET /api/v1/jobs/JOB_ID`. The web interface also uses authenticated server-sent events at `GET /api/v1/jobs/stream`; it accepts the same optional `kind` filter as the job list. Reconnecting clients receive a `jobs` event with `reset: true`, followed by changed jobs and removed IDs. This stream uses the existing browser session and access-control boundary.

The web interface cancels an active review with `POST /api/v1/jobs/JOB_ID/cancel`. This also supports a capture job after extraction, while its review is cancellable. A completed/publishing review returns a conflict instead of discarding an already saved result.
