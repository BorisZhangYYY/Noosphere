# v0.3.3.0 — 自然语言模板与三阶段图文审阅

发布于 2026-10-13。本版本调整审阅配置与图文协作方式，对齐思源插件的视角和模板配置模型。

## 改动

- Web 审阅配置只展示「审阅视角」与「文章模板」。通用去噪、图文协作、元数据保护、JSON 接口约束由系统管理。
- 文章模板使用自然语言和 Markdown 示例，描述章节、顺序、详略及讲解要求。移除正文槽位和固定章节的强制校验。
- 「基于原文」模板包含「AI 摘要」「正文」；「小白视角」包含「快速理解」「阅读前准备」「正文与讲解」。中文模板采用用户提供的原文，同时提供对应英文版。
- 审阅分三阶段：文本模型完成审阅稿与内部摘要；独立图片模型依据摘要识别每张图片的内容、功能与保留建议；文本模型结合描述、视角和模板，决定图片保留、移动或软移除。
- 识图阶段只分析，不改图片位置或编号。最后阶段返回操作计划，默认不重写正文；确有图文衔接需要时，只修改相关段落。图片可以按内容与用途放进对应要点、步骤或章节，没有写死分组规则。
- 文本模型无需识图。没有配置识图模型或识图失败时保留图片；最后阶段失败或计划不合法时保留第一阶段审阅稿和所有图片。图片仍通过既有 `removed/` 机制软移除，用户可以查看并恢复。
- 图片编号绑定原文顺序，不因移除而重新编号。审阅期间用户保存的新改动不会被最后阶段覆盖。复用已有识图结果时，摘要、提示词、模型与图片内容必须一致。
- 审阅前尝试读取模型接口公布的输入、输出与上下文容量，结合配置预算保守估算整篇请求。容量不足时直接分段，每段也在调用前按预算缩小；提示词连有效正文片段都容纳不了时，不发送生成请求。已知容量时按预算决定整篇或分段，未知容量时保留 18,000 字符保守触发阈值。分段目标仍约 4,800 字符，递归重试、原文保底和并发策略保留。最后的图片阶段使用段落与结构索引，移动图片时保留完整长文。
- 标题与可信来源元数据仍由系统组装。作者和发布时间的缺失回填仍需原文证据。内部摘要必须返回，模板可不展示摘要。
- 旧变量模板读取时转换为自然语言要求；保存配置后写入转换结果。已有审阅稿不会自动重写。
- 未达长文阈值但模型明确返回输出截断时，自动复用既有分段审阅，不直接丢失整次结果。审阅面板显示已用时、等待模型正文的提示，以及独立的文本、图片识别和图片安排阶段。
- 图片请求取消代码中隐藏的 1,024 token 输出上限，使用供应商配置预算。设置页可编辑输出预算与可选上下文容量。模型实际输出长度仍无法提前精确预测，截断恢复作为保底保留。
- 编辑模式可直接拖动图片到段落、标题前后或列表要点内，显示插入线并支持边缘滚动。删除旧的上下箭头按钮，保留删除、恢复和键盘移动。保存后位置持久化；文字块拖动留待下一版。
- 相邻块共享同一条插入线，拖回原位置不再显示可移动提示；滚动和松手时重新确认落点。文字按块拖动与标题章节折叠已记入后续迭代，标题移动应带着整节内容，折叠不影响导出全文。
- 拖动时使用小图预览，落点与滚动每帧合并更新，缓存块坐标，避免重复遍历文章和查询整页鼠标命中元素。边缘滚动随靠近程度平滑加速，不随屏幕刷新率改变速度。

- 移除来源面板中作者和发布时间下方重复的黄色缺失提示；缺失值仍可在编辑模式补录已核实内容。

## 使用

内置视角为只读。需要修改时，选择内置视角并「新建视角」，分别编辑视角与文章模板后保存。无需填写变量或声明正文槽位。可以在视角或模板中自然描述图片组织要求，例如「步骤截图放在对应步骤旁」。MCP 与 CLI 使用同一审阅流程与配置逻辑，旧槽位参数保留兼容。

图片模型单独配置，需支持识图。文本模型只收到图片的描述和功能。没有图片时跳过后两个模型阶段；有图片时通常增加一次最终文本调用，每张图片的识别、描述和功能判断合并为一次识图调用。

## 本轮边界

改动集中于审阅配置、提示词、三阶段审阅流程及手动图片拖动。抓取、搜索、Collections 和上传业务未扩展。思源插件在另一会话开发，本分支未修改插件仓库。

## 验证

完整 Dockerfile 构建通过；最终镜像内 292 项测试通过，健康、认证、前端、图片移动/移除/恢复、保存冲突保护及非 root Chromium 启动检查通过。124 项业务源码、提示词和包配置哈希与发布工作区一致。

PostgreSQL 16 下 156 项相关回归通过；两项只针对 SQLite 文件迁移的用例由常规测试覆盖。前端运行依赖漏洞检查通过，构建工具依赖未进入运行镜像。

后端 292 项通过，7 项需显式开启的浏览器测试跳过；前端 25 项通过，类型检查与生产构建通过。专项回归覆盖三阶段顺序、调用前分段与拒绝、模型容量限制、图片进入不同列表要点、跨长文段落移动、行内图片移走后的局部指代修正、不改正文、软移除与恢复、接口失败保底、稳定编号及并发保存。真实供应商验收完成 3 张图片移动、5 张软移除和 1 处局部文字调整；另验证模型容量读取、131,072 token 正文预算可用，之前截断的图片在 32,768 token 预算下正常完成识别。浏览器验证图片拖入列表要点、保存及重新打开，保持图片数量、正文内容和删除状态；同一落点只显示一处插入线，原地松手不产生未保存改动，松手落点以当前指针位置为准。原始稿未改动。拖动专项浏览器回归验证空白落点、列表内移动和停止滚动；同一测试文章 30 次合成事件更新的中位脚本耗时由 77.6 ms 降至 2.3 ms，实际手感仍需手动验收。之前分段稿保留了重复模板章节，分段后的整体组织质量仍需后续改进。
